# Fastify Website Maintainer Skill (`fastify/website`)

Specialized workflow and reference guide for maintaining, reviewing pull requests, and implementing changes in [`fastify/website`](https://github.com/fastify/website) (`@fastify/website`, deployed at [fastify.dev](https://fastify.dev)).

Repository maps, tool versions, and workflow defaults below are orientation examples. Confirm them in the target checkout before applying them; its configuration and contribution rules determine applicability. Source root observed on 2026-10-14: [fastify/website at `9ae2326`](https://github.com/fastify/website/tree/9ae232617372934813e7036e2674a6b0ae9bb7e5).

## Scope & Repository Identity

- **In Scope**: `fastify/website` (`package.json` `"name": "@fastify/website"`).
- **Source-of-Truth Boundaries (CRITICAL)**:
  - **Framework Documentation & Ecosystem List**: Never edit or commit files under `src/content/docs/` or `public/docs/`. Fastify documentation is authored in `fastify/fastify/docs/` (including `docs/Guides/Ecosystem.md`) and fetched at build time by `scripts/fetch-docs.mjs`. Use **`fastify-core`** when documentation prose or ecosystem entries need changes.
  - **Benchmarks Data**: `src/data/benchmarks.json` is fetched at build time from `fastify/benchmarks` by `scripts/download-benchmarks.mjs`. Only `scripts/frameworks.json` and the rendering components live in `fastify/website`.
  - **Static Site Roster & Sponsors**: Maintainer rosters (`LEADS`, `COLLABORATORS`, `PAST_COLLABORATORS`), `SPONSORS`, `FEATURES`, and `NAV` are maintained directly in `src/data/site.ts` (with sponsor logos in `public/organizations/`).
- **Project-Embedded UI/UX Skills (`skills-lock.json` & `.agents/skills/`)**:
  - `fastify/website` bundles two local Agent Skills in `.agents/skills/` (and symlinked in `.claude/skills/`), tracked in `skills-lock.json`:
    1. **`frontend-design`** (`.agents/skills/frontend-design/SKILL.md`, source: `anthropics/skills`): Load and follow when designing new UI sections, reshaping layouts, choosing typography/palette hierarchy, or writing UI copy so changes preserve Fastify's intentional telemetry/velocity visual identity rather than generic defaults.
    2. **`web-design-guidelines`** (`.agents/skills/web-design-guidelines/SKILL.md`, source: `vercel-labs/agent-skills`): Load and follow when reviewing UI PRs, auditing accessibility/UX, or verifying compliance with the Vercel Web Interface Guidelines (`https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`).
- **Related Fastify Skills**:
  - When reviewing a pull request or diff in `fastify/website`, pair this skill with [`fastify-code-review`](../fastify-code-review/SKILL.md) for the standardized review flow, severity classification, and Fastify maintainer tone.
  - For `fastify/fastify` core code and `docs/`: use [`fastify-core`](../fastify-core/SKILL.md).
  - For `@fastify/*` ecosystem plugins and utilities: use [`fastify-plugins`](../fastify-plugins/SKILL.md).
  - For `fastify/workflows` reusable CI workflows: use [`fastify-workflows`](../fastify-workflows/SKILL.md).

## Workflow 1: Reviewing a Pull Request in `fastify/website`

1. **Check Source-of-Truth & Generated Files**:
   - Reject PRs that commit generated files (`src/content/docs/**`, `public/docs/**`, `src/data/*.json`, `build/`, `.astro/`).
   - If a PR attempts to fix a typo in Fastify's documentation or add a plugin to the ecosystem page by editing generated files, instruct the author to open the PR against `fastify/fastify` (`docs/` or `docs/Guides/Ecosystem.md`).
2. **Verify Base-Aware Routing & Links**:
   - Confirm all internal root-absolute links (`href="/..."`, asset paths, client-side Pagefind imports) wrap paths with `withBase(...)` from `~/lib/href`.
   - Confirm doc version switching and canonical/edit links use `afterVersion(docId)` and preserve case/dot structure.
3. **Audit UI, Theme, Security & Accessibility (with `web-design-guidelines` & `frontend-design`)**:
   - When reviewing `.astro` pages, components, or CSS changes, load the repository's embedded **`.agents/skills/web-design-guidelines/SKILL.md`** and **`.agents/skills/frontend-design/SKILL.md`**.
   - Check that components use semantic CSS tokens (`bg-bg`, `bg-surface`, `text-fg`, `text-fg-soft`, `text-muted`, `border-border`, `text-amber-ink`) from `src/styles/tokens.css` so both dark mode (default) and `[data-theme="light"]` render with proper contrast.
   - Verify any `set:html` or client-side `innerHTML` sanitizes untrusted/markdown strings with `DOMPurify.sanitize(...)` (`isomorphic-dompurify`) or HTML escaping.
   - Check keyboard accessibility (`:focus-visible`, `<dialog>` Escape handling, `aria-label`, `aria-current="page"`, `prefers-reduced-motion: reduce`) and Web Interface Guidelines compliance.
4. **Verify Build-Time Data Scripts (`scripts/`)**:
   - Ensure changes to `scripts/*.mjs` handle network errors/rate-limits gracefully and allow local builds without `GH_TOKEN` to succeed (using cached/existing snapshots or fallback values).
5. **Check Linting, Types & Workflows**:
   - Confirm `npm run lint` (`biome check`), `npm run check` (`astro check`), and `npm run build:website` pass.
   - In `.github/workflows/`, verify third-party actions are pinned to full 40-character commit SHAs and untrusted PR contexts are handled safely.

## Workflow 2: Implementing Features or Fixes in `fastify/website`

1. **Load Relevant Reference Guide(s) & Project-Embedded Skills**:
   - Modifying build scripts (`scripts/`), content collections (`src/content.config.ts`), or data (`src/data/`) -> read [references/architecture-and-data-pipeline.md](references/architecture-and-data-pipeline.md).
   - Modifying Astro pages (`src/pages/`), components (`src/components/`), styles (`src/styles/`), or client services (`src/services/`, `src/lib/`) -> read [references/components-and-styling.md](references/components-and-styling.md) **AND** load the repository's embedded skills:
     - **`.agents/skills/frontend-design/SKILL.md`** when building or redesigning visual components, layouts, typography, motion, or UI copy.
     - **`.agents/skills/web-design-guidelines/SKILL.md`** to audit the resulting UI against Web Interface Guidelines.
   - Running checks, fixing Biome lint issues, or updating `.github/workflows/` -> read [references/validation-and-workflows.md](references/validation-and-workflows.md).
2. **Ensure Build Data Exists Before Typechecking or Building**:
   - Because `src/data/*.json` and `src/content/docs/` are git-ignored, TypeScript imports like `import benchmarksData from "~/data/benchmarks.json"` and `import versionsData from "~/data/versions.json"` will fail in a fresh checkout until `npm run build:data` has been executed.
3. **Implement Changes**:
   - Use the `~/*` path alias for all imports under `src/`.
   - Format and lint with Biome (`npm run lint` / `npm run lint:fix` — note: Biome uses tabs for indentation by default in this repo).
4. **Validate**:
   - Run `npm run lint` (`biome check`).
   - Run `npm run check` (`astro check`).
   - Run `npm run build:website` to verify the full data pipeline, Astro static generation, and Pagefind search indexing.
   - For UI/routing changes, run the affected [production preview checks](references/validation-and-workflows.md) and report browser observations separately from build results.

## Pre-Submission Checklist

- [ ] No git-ignored generated files (`src/content/docs/`, `public/docs/`, `src/data/*.json`, `build/`) are staged.
- [ ] All internal root-relative URLs use `withBase()` from `~/lib/href`.
- [ ] Dynamic HTML uses `DOMPurify.sanitize()` or explicit HTML entity escaping.
- [ ] Both dark (default) and light (`[data-theme="light"]`) themes are supported via semantic tokens.
- [ ] UI/UX changes follow `.agents/skills/frontend-design/SKILL.md` and pass `.agents/skills/web-design-guidelines/SKILL.md` checks.
- [ ] `npm run lint` (`biome check`) passes with zero errors.
- [ ] `npm run check` (`astro check`) passes with zero errors.
- [ ] `npm run build:website` succeeds and generates `./build` with Pagefind indexes.
- [ ] Relevant production-preview interactions are verified in a browser, or reported as `Not run` with a reason.

# Fastify Core Architecture & Code Patterns (`code`)

Load this reference when inspecting or modifying `fastify.js`, `lib/*.js`, or `build/*.js` in `fastify/fastify`.

---

## 1. Core Module Map (`fastify.js` & `lib/`)

Understanding where responsibilities live in `fastify/fastify` prevents misplaced logic and broken encapsulation:

| File | Responsibility |
| --- | --- |
| `fastify.js` | Root factory `fastify(options)`, server initialization, plugin registration (`avvio`), root decorators/hooks/schemas setup, and CJS/ESM export assignments (`fastify`, `default`, `errorCodes`, `LogController`). |
| `lib/server.js` | Creates the underlying Node.js `http`, `https`, or `http2` server (or custom `serverFactory`), handles `listen()`, port/socket binding, and `keep-alive` connection tracking. |
| `lib/route.js` | Route registration (`fastify.route()`, `.get()`, `.post()`, etc.), `find-my-way` router integration, route-level hook/schema/config preparation, and `onRoute` hook execution. |
| `lib/context.js` | Per-route `Context` constructor holding compiled schemas, hooks, parsers, error handlers, reply serializers, and route `config`. |
| `lib/hooks.js` | `Hooks` class managing application and request/reply lifecycle hooks, validation of hook names/handlers, and hook runner functions (`hookRunnerApplication`, `hookRunnerGenerator`, `onSendHookRunner`, `onRequestAbortHookRunner`). |
| `lib/handle-request.js` | Core per-request state machine after routing: executes `preParsing` -> body parsing -> `preValidation` -> schema validation -> `preHandler` -> route handler -> `reply.send()`. |
| `lib/request.js` | `Request` constructor, prototype getters (`headers`, `params`, `query`, `body`, `ip`, `ips`, `hostname`, `protocol`, `method`, `url`), and per-request validation function caching. |
| `lib/reply.js` | `Reply` constructor, `reply.send()`, `reply.code()`, `reply.header()`, `reply.serialize()`, `onSend` / `preSerialization` / `onError` / `onResponse` lifecycle execution, and payload stream handling. |
| `lib/content-type-parser.js` | `ContentTypeParser` registry (`application/json`, `text/plain`, custom string/RegExp parsers), `rawBody` / stream consumption, `bodyLimit` enforcement, and prototype-poisoning protection (`secure-json-parse`). |
| `lib/decorate.js` | `decorate`, `decorateRequest`, `decorateReply`, `hasDecorator`, `hasRequestDecorator`, `hasReplyDecorator`, and reference-type/dependency checks. |
| `lib/plugin-override.js` | `avvio` `override` implementation that creates child encapsulated `FastifyInstance` contexts (`Object.create(old)`) inheriting cloned `Request`/`Reply` constructors, hooks, schemas, decorators, and parsers. |
| `lib/schema-controller.js` & `lib/schemas.js` | Schema bucket management (`addSchema`, `getSchema`, `getSchemas`) and compilation via `@fastify/ajv-compiler` and `@fastify/fast-json-stringify-compiler`. |
| `lib/error-handler.js` & `lib/four-oh-four.js` | Error handling chain (`setErrorHandler`, fallback error serialization, status code clamping) and encapsulated 404 routing (`setNotFoundHandler`). |
| `lib/log-controller.js`, `lib/logger-factory.js`, `lib/logger-pino.js` | Logger creation, Pino integration, child logger factories, and route-level log levels/serializers. |
| `lib/symbols.js` | Centralized `Symbol('fastify.*')` definitions for all private properties on `FastifyInstance`, `Request`, `Reply`, and `Context`. |
| `lib/errors.js` | All `FST_ERR_*` error constructors created via `@fastify/error`. |
| `lib/warnings.js` | All `FSTWRN*`, `FSTSEC*`, and `FSTDEP*` warnings created via `process-warning`. |
| `lib/wrap-thenable.js` | Bridges `async` / `Promise`-returning route handlers and hooks with `Reply` error/payload settlement. |

## 2. Build Sources & Generated Validator Integrity

The `build/` directory contains maintained source scripts. Two files in `lib/` are **auto-generated**, intentionally committed, and ignored by ESLint (`eslint.config.js`):

1. **`lib/config-validator.js`** — Generated by `build/build-validation.js` using `@fastify/ajv-compiler/standalone`.
   - Whenever you add, remove, or modify a server initialization option (`connectionTimeout`, `keepAliveTimeout`, `bodyLimit`, `handlerTimeout`, `allowErrorHandlerOverride`, `routerOptions.*`, etc.), edit **`build/build-validation.js`** (`defaultInitOptions` and `schema`), **never** `lib/config-validator.js` directly.
2. **`lib/error-serializer.js`** — Generated by `build/build-error-serializer.js` using `fast-json-stringify` standalone mode.
   - Edit `build/build-error-serializer.js` when changing the default error JSON schema.
3. **Mandatory Regeneration & Integrity Check:**
   Confirm the commands in the checkout's `package.json`. During implementation, after modifying a generator, run:
   ```bash
   npm run build:validation
   npm run test:validator:integrity
   ```
   `npm run test:validator:integrity` regenerates both files and runs `git diff --quiet` on `lib/error-serializer.js` and `lib/config-validator.js` (this is also enforced during `prepublishOnly`).
   During review, run this mutating check only in an isolated temporary checkout of the reviewed head. Report its exit code and generated differences; do not stage output to conceal a mismatch. If prerequisites are unavailable, report `Not run` rather than modifying the user's checkout.
4. **Version Sync (`build/sync-version.js`):**
   - `const VERSION = '...'` in `fastify.js` is synchronized from `package.json#version` by `npm run build:sync-version` during release preparation. Do not manually bump `VERSION` in feature/bug-fix PRs.

## 3. Encapsulation & `lib/plugin-override.js`

Fastify's encapsulation model is built on `avvio`'s `override(old, fn, options)` hook in `lib/plugin-override.js`:
- When `fastify.register(plugin)` runs without `Symbol.for('skip-override')` (i.e., not wrapped with `fastify-plugin`), `lib/plugin-override.js`:
  1. Creates a new instance via `const instance = Object.create(old)`.
  2. Derives child `Request` and `Reply` classes (`Request.buildRequest(old[kRequest])`, `Reply.buildReply(old[kReply])`) so request/reply decorators added in the child plugin do **not** mutate the parent's `Request.prototype` or `Reply.prototype`.
  3. Clones `[kHooks]`, `[kContentTypeParser]`, `[kRoutePrefix]`, `[kLogLevel]`, `[kSchemaController]`, `[kErrorHandler]`, and `[kPluginNameChain]`.
- **Rule for New Instance Properties:** Any new internal state attached to `fastify` in `fastify.js` must use a symbol from `lib/symbols.js` and be explicitly handled (cloned, inherited, or reset) in `lib/plugin-override.js` if child plugin scopes can override it.

## 4. Standardized Errors (`lib/errors.js`) & Warnings (`lib/warnings.js`)

### Adding or Modifying `FST_ERR_*` Errors
1. Define the error in `lib/errors.js` using `createError` from `@fastify/error`:
   ```js
   FST_ERR_MY_NEW_CODE: createError(
     'FST_ERR_MY_NEW_CODE',
     "Descriptive message with '%s' placeholder",
     500,
     TypeError
   )
   ```
2. Add the corresponding TypeScript type property to `FastifyErrorCodes` in `types/errors.d.ts`.
3. Add a type assertion in `test/types/errors.tst.ts`.
4. Document the error code in `docs/Reference/Errors.md` (matching the exact code and message).

### Adding Warnings or Deprecations (`lib/warnings.js`)
1. Use `createWarning` from `process-warning` in `lib/warnings.js`.
2. **Never Reuse Historical Codes:**
   - `FSTDEP001`–`FSTDEP021` were used in v4; `FSTDEP022`–`FSTDEP025` were used in v5.
   - `FSTWRN001`–`FSTWRN002` were used in v4.
   - Always assign the next unused sequential code (`FSTWRN*`, `FSTSEC*`, or `FSTDEP*`).
3. Document the warning/deprecation in `docs/Reference/Warnings.md`.
